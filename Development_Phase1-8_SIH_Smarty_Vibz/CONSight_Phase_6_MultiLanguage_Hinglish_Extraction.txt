======================================================================
1. PHASE 6 GOAL
======================================================================

Enable CONSight to understand construction-site progress messages written
in multiple supported languages and common Indian construction-site
Hinglish/code-mixed language.

Examples:

English:
"XX-101 spool erection started in Area B."

Hinglish:
"XX-101 ka spool erection start kiya."

Hindi:
"XX-101 का स्पूल इरेक्शन एरिया बी में शुरू किया।"

Mixed:
"Foundation ka concreting complete ho gaya, Area A."

The key requirement is NOT generic translation.

The system must preserve the operational meaning of the original field
message and convert it into the SAME structured progress representation
already used by the existing system.

======================================================================
6. STRUCTURED EXTRACTION CONTRACT
======================================================================

The model must NOT directly modify database records.

It should produce structured candidate information compatible with the
existing Progress Event pipeline.

Fields may include only fields already supported by the repository,
plus narrowly justified Phase 6 metadata such as:

- original_text
- detected_language
- is_code_mixed
- normalized_text
- extracted_activity_reference
- discipline
- location
- progress/status
- actual date/time
- notes

IMPORTANT:
If a value is not explicitly present or safely derivable according to
the existing extraction rules, return null/unknown.

Do not hallucinate:
- activity IDs
- dates
- locations
- quantities
- equipment
- personnel
- percentages
- schedule relationships
- completion states

Example:

Input:
"XX-101 ka spool erection start kiya."

Acceptable:
activity_reference = "XX-101"
activity_description = "spool erection"
status = "started"
language = "hinglish"

Unacceptable:
location = "Area B" if not present
date = today's date if not supplied by the message/event metadata
progress = 50%
confidence = HIGH merely because the sentence is clear

======================================================================
7. NORMALIZATION RULES
======================================================================

Normalization must preserve meaning.

Examples:

"ka" / "ki" / "ke"
→ grammatical relationship, not a project field

"start kiya"
→ started

"complete ho gaya"
→ completed

"chal raha hai"
→ in progress

"kal complete hoga"
→ future expectation, NOT completed

"abhi tak nahi hua"
→ not completed / pending depending on existing schema

Never convert future or conditional statements into actual progress.

The original message must remain recoverable for audit/debug purposes.

======================================================================
9. TEMPORAL SEMANTICS
======================================================================

Phase 6 must preserve the distinction between:

PAST:
"kal concreting kiya"
→ actual progress happened yesterday

PRESENT:
"aaj concreting kar rahe hain"
→ current/in-progress

FUTURE:
"kal concreting karenge"
→ planned/future statement, not actual completion

AMBIGUOUS:
"kal concreting?"
→ unclear; require clarification/review

The model must not silently replace missing dates with the current date.

Use existing event timestamps where the application already supplies
provider metadata, but distinguish event receipt time from stated
activity time.
